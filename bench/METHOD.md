# 측정 방법과 결과

메모리가 실효를 가지려면 사슬 전체가 성립해야 한다.

```
질문 → [D1 트리거] → [D2 검색] → [D3 반영] → 답변
```

원래 측정에서 D2=0.60(P@1), D3=0.86으로 뒤쪽은 멀쩡했고 **D1=0.10**이 전부를 잡아먹었다.
이 저장소의 SessionStart 훅은 D1만 겨냥한다.

## 지표를 바꾼 이유 — D1′

기존 D1은 조회 스킬 **호출 여부**를 셌다. 목차를 주입하면 호출 없이도 답변이 메모리를 반영하므로,
호출 기반 지표는 이 개선을 **퇴보로 읽는다**(0.10 → 0.00).

**D1′는 결과를 잰다** — 강제하지 않은 답변이 `expected_signals` 또는 메모리 ID를 담는가.

신호는 강약을 나눈다. 4자 이하 토큰(`그리드`, `분리`)은 메모리 없이도 나올 수 있어 **weak**로 분리하고,
집계는 **strong만** 쓴다. 이 구분이 없으면 지표가 부풀려진다 (실측 0.45 → 0.70).

## 조건 설계

| 조건 | 메모리 | 목차 주입 | 시점 |
|------|--------|----------|------|
| auto | 있음 | 없음 | 3개월 전 baseline |
| **C** | 있음 | **없음** | 측정일 |
| **B** | 있음 | **있음** | 측정일 |

**C가 핵심이다.** B를 과거 baseline과만 비교하면 모델 버전·메모리 증가분이 섞인다.
같은 날·같은 모델·같은 메모리·같은 샌드박스에서 주입만 제거한 대조군이 있어야 귀속이 성립한다.

## 결과 (N=20)

| 조건 | D1′ strong | 95% CI (Wilson) | 조회 호출률 |
|------|-----------|-----------------|------------|
| auto | 0.45 | — | 0.10 |
| C | 0.45 | [0.26, 0.66] | 0.15 |
| **B** | **0.85** | [0.64, 0.95] | 0.00 |

**개선 8건, 퇴보 0건. McNemar exact 양측 p = 0.0078.**

C(0.45)가 3개월 전 auto(0.45)와 정확히 일치했다 — 표류가 이 지표를 움직이지 않았으므로
B의 +0.40은 주입에 귀속된다.

### 질적 관찰

한 프로브에서 모델이 메모리를 읽고 실제 코드와 대조해 **"메모리에는 확인 대기로 남아 있는데
실제로는 구현이 끝나 있다"** 고 낡음을 지적했다. 대조군은 메모리 존재를 몰라 일반론만 답했다.
주입이 조회를 대체한 게 아니라 검증까지 유도한 사례다.

## 재현

```bash
cp bench/probes.example.jsonl bench/probes.jsonl   # 본인 메모리에 맞게 작성
TARGET_PROJECT=/path/to/your/project bash bench/runner_sandbox.sh C
TARGET_PROJECT=/path/to/your/project bash bench/runner_sandbox.sh B
python3 bench/compare_conditions.py C B
```

프로브는 **본인 메모리에 실제로 있는 내용**으로 써야 한다. `expected_signals`는
"메모리를 봤다면 나올 문자열"이고, 짧은 일반 단어는 피한다.

## 러너가 샌드박스인 이유

프로브는 질문이 아니라 **명령문**이다. 실제 워크스페이스에서 `--dangerously-skip-permissions`로
돌렸더니 "이 변경사항 커밋하고 푸시해줘" 프로브가 미커밋 작업물 12파일을 실제로 커밋하고 푸시했다.
버그가 아니라 지시를 정확히 이행한 결과다.

`runner_sandbox.sh`는 임시 디렉토리에 프로젝트 컨텍스트만 복사하고 remote 없는 git 저장소를 만든다.

> **격리가 아니라 완화다.** 에이전트는 여전히 파일시스템 어디든 접근할 수 있고, 실제로 한 프로브가
> 샌드박스 밖 프로젝트 디렉토리를 읽었다. 없애는 것은 *기본 대상*일 뿐이다 — cwd가 깨끗한
> 스크래치 저장소라 쓸어담을 것도 보낼 곳도 없다. 진짜 격리가 필요하면 VM·컨테이너를 써라.

## 한계

- **N=20.** CI가 넓다. 방향성만 읽을 것. 효과 크기로 인용하지 말 것.
- **프로브 저작자 편향.** 프로브를 시스템 사용자가 썼다. 독립 작성자가 만든 프로브가 필요하다.
- **자기 평가.** 주입 훅 설계자와 측정 설계자가 같다.
- **컨텍스트 누출.** `expected_signals` 일부는 대상 프로젝트의 `CLAUDE.md`에도 존재한다.
  strong/weak 분리로 완화했으나 완전하지 않다. 완전히 가르려면 "CLAUDE.md는 있고 메모리만 없는"
  네 번째 조건이 필요하다.
- **한국어 단일 측정.** 파일명 키워드 우위는 언어 특성일 수 있다.
- **D2·D3 미재측정.** 이번에 잰 것은 D1′뿐이다.

실제 프로브·결과 파일은 개인·클라이언트 정보를 담고 있어 공개하지 않는다.
