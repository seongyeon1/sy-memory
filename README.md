# sy-memory

Claude Code용 파일 기반 세션 메모리. 마크다운 파일 몇 개와 훅 두 개가 전부다.

> Session memory for Claude Code, as plain markdown plus two hooks.
> Built around one measured finding: the bottleneck was never retrieval — it was that
> the model never went looking.

---

## 왜 만들었나

메모리 시스템을 붙여놓고 6개월을 썼는데 체감이 없었다. 재보니 이유가 나왔다.

메모리가 실제로 도움이 되려면 세 단계가 전부 성립해야 한다.

```
질문 → [D1 트리거] → [D2 검색] → [D3 반영] → 답변
       모델이 찾아볼   맞는 걸     그대로
       생각을 하는가?   찾는가?    답하는가?
```

20개 프로브로 측정한 결과:

| 단계 | 값 |
|---|---|
| D1 자동 트리거 | **0.10** (20개 중 2개) |
| D2 검색 정확도 (P@1) | 0.60 |
| D3 행동 반영 | 0.86 |

검색은 멀쩡했다. 한국어 메모리·한국어 질의 조합에서는 mem0보다 P@1이 1.5~2.4배 높았다 —
파일명과 첫 줄에 사람이 의식적으로 키워드를 박아두기 때문이다.

**문제는 모델이 그냥 안 찾아본다는 것이었다.** "ralph 패턴 뭐야?"처럼 메모리에 명백히 있는
질문에도 조회가 일어나지 않았다. 트리거가 0.10이면 뒤가 아무리 좋아도 곱해서 사라진다.

존재를 모르는 메모리는 없는 메모리다.

## 효과

20개 프로브, 같은 날·같은 모델·같은 메모리·같은 샌드박스에서 **목차 주입만** 켜고 껐다.

| 조건 | D1′ (답변이 메모리를 반영) | `sy:recall` 호출 |
|---|---|---|
| 주입 없음 | 0.45 `[0.26, 0.66]` | 0.15 |
| **주입 있음** | **0.85** `[0.64, 0.95]` | **0.00** |

**개선 8건, 퇴보 0건. McNemar exact 양측 p = 0.0078.**

호출률이 0으로 떨어진 것에 주목할 것. **목차가 있으면 조회할 이유가 없다.**
호출 여부로 재는 기존 지표였다면 이 변화는 0.10 → 0.00, 즉 완전한 퇴보로 읽혔을 것이다.
그래서 지표부터 바꿔야 했다 — 메커니즘이 아니라 결과를 재도록.

3개월 전 baseline도 0.45로 동일했다. 시간에 따른 표류가 아니라 주입의 효과다.

측정 방법·한계·재현 절차는 [`bench/METHOD.md`](bench/METHOD.md).
실제 프로브와 결과 파일은 개인·클라이언트 정보를 담고 있어 공개하지 않는다 — 도구와 방법만 있다.

## 어떻게 고쳤나

**세션이 시작될 때 목차를 그냥 넣어준다.** 조회를 유도하는 게 아니라 존재를 공짜로 만든다.

```
# 저장된 메모리 목차 (SY Memory)
## 프로젝트 — 21개 (+ session 로그 28건은 Glob으로 조회)
- feedback_commit_style.md — 커밋 메시지에 Co-Authored-By 트레일러 넣지 않음
- lesson_pixel_art_iteration.md — 픽셀 아트는 캔버스 크기 먼저 고정...
## 전역 — 33개
...
```

세 가지가 이 설계의 핵심이다.

**예산은 구조로 보장한다.** 항목 길이를 사람에게 강제하는 대신 훅이 주입 시점에 자른다
(`SY_MEMORY_BUDGET`, 기본 5,000자). 규율에 의존하는 인덱스는 결국 메모리 파일의 사본으로 퇴화한다.

**세션 로그는 목차에서 뺀다.** `session_*.md`는 날짜 저널이지 주제로 검색되는 지식이 아닌데
개수로는 절반이 넘는다. 개수만 알리고 자리를 지식 항목에 준다.

**INDEX에 없는 파일도 노출한다.** 저장은 됐는데 인덱스 갱신을 빠뜨린 파일이 실제로 3개 있었다.
목차 방식에서 orphan은 존재하지 않는 파일과 같다.

## 메모리가 틀렸을 때가 더 위험하다

만들면서 발견한 것 중 D1보다 심각한 게 있었다.

한 세션이 `~/.sy/memory/`에 `ls`를 시도했다가 막히자 **"이 디렉토리는 쓰기 차단됨"** 이라고
메모리에 적었다. 실제로 막힌 건 `ls`뿐이고 읽기·쓰기는 처음부터 정상이었다.

그 다음 세션은 `ls`를 한 번 더 해보고 **"여전히 차단됨"** 이라고 적었다.
세 번째 세션도 같은 말을 반복했다. **3주 동안 아무도 쓰기를 시도해보지 않았다.**
"여전히"라는 단어가 재검증을 대신했고, 인용이 검증으로 위장했다.

메모리가 도움을 못 준 게 아니라 **틀린 확신을 만들어냈다.** 이건 음의 가치다.

그래서 메모리에 적으면 안 되는 종류를 구분한다.

| 종류 | 저장 | 이유 |
|---|---|---|
| 결정·선호 ("엠대시 대신 콜론") | O | 사람이 정한 것 |
| 도메인 사실 | O | 안정적 |
| **환경·능력 주장** ("X는 차단됨") | **X** | 세션·권한·버전마다 뒤집힘 |

굳이 적어야 하면 반증 명령을 함께 적는다.

```yaml
---
type: lesson
verify: "python3 -c \"...; print('WRITABLE')\""
---
```

`verify:`가 있는 메모리는 목차에 **재검증 대상**으로 표시되고, 조회 스킬은 본문을 인용하기 전에
그 명령을 실행하도록 지시받는다. 결과가 본문과 다르면 결과를 따르고 메모리를 정정한다.

## 설치

```bash
git clone https://github.com/seongyeon1/sy-memory.git
cd sy-memory
./install.sh          # 이 프로젝트만  (.claude/settings.json)
./install.sh --user   # 모든 프로젝트  (~/.claude/settings.json)
```

스킬까지 쓰려면 `cp -r skills/* .claude/skills/`.
제거는 `./install.sh --uninstall` — 훅만 지우고 메모리 파일은 건드리지 않는다.

의존성 없음 (python3 stdlib + bash).

## 저장 규칙

| 위치 | 접두사 | 기준 |
|---|---|---|
| `~/.sy/memory/` | `user_` `feedback_` `tech_` `lesson_` | 프로젝트를 넘어 재사용되는 것 |
| `.sy-memory/` | `arch_` `decision_` `issue_` `session_` | 이 저장소에서만 의미 있는 것 |

두 디렉토리는 `[[위키링크]]` 하나의 네임스페이스를 공유한다.

환경 변수로 경로를 바꿀 수 있다 — `SY_MEMORY_GLOBAL`, `SY_MEMORY_PROJECT`, `SY_MEMORY_BUDGET`,
`SY_MEMORY_INCLUDE_SESSIONS=1`.

## 점검

```bash
python3 scripts/lint_index.py ~/.sy/memory .sy-memory
```

INDEX 누락(orphan), 실재하지 않는 `[[링크]]`, 중복 항목, 대상 없는 항목을 잡는다.
링크는 넘겨준 디렉토리 전체를 합쳐서 해석하므로 교차 참조를 오탐하지 않는다.
길이 초과는 경고로만 알린다 — 어차피 주입 시 잘린다.

```bash
bash tests/test_hooks.sh    # 25개, 모델 호출 없음
```

## 구성

```
hooks/session_start.py   목차 주입 (예산 자동 조정)
hooks/stop.py            세션 종료 시 저장 요청
skills/sy-recall/        목차 → 본문 조회
skills/sy-save/          저장 규칙
scripts/lint_index.py    무결성 점검
install.sh               훅 등록 (멱등, 다른 훅 보존)
tests/test_hooks.sh      회귀 테스트
```

## Stop 훅이 하지 않는 것

이전 버전은 "짧은 세션이라도 반드시 저장하라"고 지시했다. 그래서 저장할 게 없는 세션이
없는 교훈을 지어냈다. 지금은 **생략이 정식 결과**다 — 모델이 사유와 함께 건너뛸 수 있다.

빈 메모리가 틀린 메모리보다 낫다.

또한 훅이 기존 파일 목록을 직접 넘겨준다. "중복을 확인하라"고만 하고 확인할 대상을 안 주면
중복은 그대로 생긴다 (실제로 생겼다).

## 한계

- **N=20.** 신뢰구간이 넓다. 방향은 보여주되 정밀한 효과 크기로 읽지 말 것.
- **프로브를 설계자가 썼다.** 자기 시스템에 유리한 패턴이 섞였을 수 있다.
- 프로브 일부는 대상 저장소의 `CLAUDE.md`에도 있는 내용을 묻는다. 그래서 대조군 없이는
  메모리 귀속을 주장할 수 없다 — `bench/` 참조.
- 한국어 환경에서만 측정했다. 키워드 우위는 언어 특성일 수 있다.
- `verify:` 재검증은 **지시**이지 강제가 아니다. 모델이 건너뛸 수 있다.
